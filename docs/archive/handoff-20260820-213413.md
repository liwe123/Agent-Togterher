## 2. 项目规范化接力约定（必读 · 用于接力）

本项目的开发/文档/运维全程受 `docs/Agent任务守则.md` 约束。接力 Agent 必须按以下 4 守则作业（细节以守则原文为准）：

- **守则① 改动可追溯**：任何改动必须上《改动表》（`docs/PRD.md` 表格 + `docs/Agent_Console_变更追踪.xlsx`）；**改动内容一律中文**（产品名如 `Cursor`、文档路径 `docs/prd/...`、类型 `Requirement`、提交链接等允许）。《改动表》由 `docs/generate_change_log.py` 从 git 历史自动生成，禁止手改 xlsx。
- **守则② 类型先判后做**：动手前判 `Requirement` / `BUG` / `Optimization`。若为 **Requirement 必须写 PRD 并三处同步**：`docs/prd/PRD-<功能名>.md` + 根目录 `PRD.html` + `docs/PRD.md` 索引行。BUG/Optimization 不写 PRD。
- **守则③ 测试与验收**：A/B 测试 + 冒烟测试必做（后端 `pytest backend/tests`；前端 `npm run build`+`npm test`+`npm run lint`）；功能/视觉类须 A/B 对比并记录结论。完成后**必须再派一个独立子 Agent 做验收**（只校验不修改），核对：改动表已记录且中文无误 / PRD 三处同步 / 测试无回归 / 重跑两脚本与 git 历史一致；验收结论写入改动表备注，通过才进推送。
- **守则④ 推送**：Conventional Commits（`feat:`/`fix:`/`docs:`/`optimize:`/`refactor:`）；`git add` 仅加真实改动文件，**禁止 `git add -A`**，排除 `docs/*_备份.xlsx`、`__pycache__/`、`.workbuddy/`；默认分支 `main` 直推 `liwe123/Agent-Togterher`；**禁止强推**；推送前重跑两脚本对齐文档。

### 关键约定（易踩坑）
- **regen 提交自身行的惯例**：`generate_change_log.py` 的 `is_excluded` 仅当提交所有改动文件都在 `SKIP_PATHS={docs/build_prd_html.py, PRD.html, docs/PRD.html}` 才跳过；regen 提交还改 `docs/PRD.md`/xlsx/脚本，故**必然生成自身行**——这是仓库既定惯例（C-133~C-138 皆如此，最新 regen 提交的行落在下次同步），**不算失同步**，验收时按此判定。
- **中文改动内容**：不能出现 `MessageHub`/`output.md`/`docker-compose` 等英文代码标识符；中文化表述如「消息中枢」「产出文件」「光标桥接器」「集成节点表」。
