| 1 | PyPI 网络全面失败，venv 装 alembic/pytest 卡死 | ali/yun/清华镜像断流 + 官方直连超时；litellm 巨型依赖树拖垮全量下载 | 宿主 `pip download --no-deps` 下纯 Python wheel → `docker cp` 进容器 → `pip install --no-index --target /tmp/pylibs`；单包/小集下载能成功 |
| 2 | CI 失败（test_basic_startup 连 PG） | CI 无 PostgreSQL 服务，默认 DATABASE_URL=postgres，lifespan init_db 连 db 容器名失败 | `.github/workflows/python-package-conda.yml` pytest 步骤注入 `DATABASE_URL=sqlite+aiosqlite`，测试策略与生产默认解耦 |
| 3 | autogenerate 每次报 3 个 remove_constraint 噪音 | `Enum(create_constraint=True)` 在 SQLite 上列内 CHECK 不写进迁移脚本，compare_metadata 报 diff | `enums.py` 改 `create_constraint=False`；权衡：PG 失去 DB 级 CHECK（ORM 层 `validate_strings=True` 仍校验） |
| 4 | Docker 后端 + 宿主 Agent 拓扑死结 | 容器内无 codex 二进制，CodexBridge `create_subprocess_exec("codex")` FileNotFoundError；codex 路线仅本机裸跑可用 | P0 新增 `start-local.bat` 混合模式：db/redis 容器 + 宿主 backend/frontend，backend 子进程继承宿主 PATH 找到 codex |
| 5 | `--skip-git-repo-check` 与调研文档安全基线冲突 | bridge 任务目录非 git repo，硬编码该 flag 绕过信任检查 | 改 `BRIDGE_CODEX_SKIP_GIT_CHECK` 可配；**默认 True 向后兼容**（默认 False 会让现有 CodexBridge 全失败），P5 worktree 落地后切 False。已同步修正计划文档措辞 |
| 6 | start-local.bat 引号嵌套坑 | `cmd /k "cd backend && set "X=.." && "exe" ..."` 内层引号破坏 cmd 解析 | 用 `start /D backend` 设工作目录避免 cd；`cmd /k ""%PYTHON_BIN%" -m ..."`（cmd 剥首尾引号规则）；环境变量父脚本 set 后子 cmd 继承 |
| 7 | 健康轮询死循环风险 | db 永不 healthy / backend 永不起时脚本卡死 | 加计数器：db/backend 各 120s 超时后 warn/error 退出 |

## 4. 改动的要求（守则纪律，每次改动必走）

参照 `docs/Agent任务守则.md`，快速检查清单：

### 4.1 类型先判后做
| 类型 | 信号 | PRD |
|---|---|---|
| **Requirement** | 新功能/新能力/新页面 | **必须写**，同步 `docs/prd/` + `PRD.html` + `PRD.md` 索引三处 |
| **BUG** | 修复缺陷/`fix` | 不写 |
| **Optimization** | 重构/文档/流程工具/同步合并 | 不写 |

### 4.2 改动表
- `docs/Agent_Console_变更追踪.xlsx`，14 列（表头第 2 行，数据从第 3 行），**改动内容 H 列一律中文**
- 由 `generate_change_log.py` 从 git 历史**自动生成**；类型错改 `CURATED`/`CURATED_BY_SUBJECT` 重跑，**绝不在 xlsx 手改**
- Bug 类型写 `BUG`（全大写，Excel 配色匹配）

### 4.3 测试（必做）
- 后端：`pip install -r backend/requirements-dev.txt` → `cd backend && DATABASE_URL=sqlite+aiosqlite pytest tests/`（**必须设 DATABASE_URL=sqlite**，否则 lifespan 连 PG 失败）
- 前端：`npm run build` + `npm test` + `npm run lint`
- 功能/视觉类做 A/B 对比，结论写入改动表

### 4.4 独立子 Agent 验收（只校验不修改）
所有改动做完后派一个子 Agent 核对：改动表格式/中文、PRD 三处同步、A/B+冒烟无回归、重跑脚本后改动表与 git 一致。**验收只校验不修改**；不通过打回修复复验，通过才推送。

### 4.5 同步脚本（提交后必跑）
```bash
# 隔离 venv：C:\Users\Administrator\.workbuddy\binaries\python\envs\default\Scripts\python.exe
python docs/generate_change_log.py   # 重生 PRD.md CHANGELOG + xlsx
python docs/build_prd_html.py        # 重生 PRD.html
```
依赖 `openpyxl` + `markdown`（已装隔离 venv）。**顺序坑**：先提交特性 commit → 再跑脚本（脚本依赖 git log）→ 脚本产物 → 再提交 docs。

### 4.6 提交推送
- Conventional Commits：`feat:` / `fix:` / `docs:` / `optimize:` / `refactor:`（前缀决定改动表类型推断）
- `git add` **只加真实改动文件**；禁 `git add -A`；排除 `__pycache__/`、`.workbuddy/`、`*_备份.xlsx`
- `git push origin main`；回滚用 `git revert`，禁 `--force`
