### BUG-2 ｜ A2：配额限流为进程内内存计数，多实例下失效 ｜ 优先级：高（真实风险）

**需求要求**：每分钟限流（`QuotaConfig.rate_limit_per_minute`，默认 60，表 `quota_configs`）必须在 api + worker 多进程部署下全局生效。代码内 TODO 自认：`backend/app/services/quota_service.py` L98 原文「TODO: 多进程/多实例部署下需替换为 Redis 固定窗口或令牌桶限流，否则各实例各自计数。」

**定位**：
- `backend/app/services/quota_service.py` L97-122：模块级 `_rate_limit_buckets: dict[int, deque[float]] = defaultdict(deque)`（L99）+ `_check_rate_limit(workspace_id, limit) -> bool`（L102-117，`time.monotonic()` 滑窗）+ `reset_rate_limit_state()`（L120-122，测试隔离用）。
- 调用点仅 2 处：`app/core/message_hub.py` L285 `_enforce_quota()` 内调 `check_workspace_quota`，L292 抛 `AppError(429)`；`app/api/v1/endpoints/workflows.py` L277 调用、L279 抛 429。
- Redis 设施现成：`app/core/config.py` L17 `redis_url`（默认 `redis://localhost:6379/0`）；client 先例 `app/websocket/distributed.py` L36 `redis.from_url(redis_url, decode_responses=True)`；`requirements.txt` L8 已有 `redis>=5.2,<8.0`。
- **附带缺口**：`POST /api/tasks`（`app/api/v1/endpoints/tasks.py` L153-175）不走配额检查（0828 审查报告 §三.3 并发上限旁路同一路径），本项一并补。

**修复方法**（推荐 Redis 固定窗口，实现最简且与 TODO 建议一致）：
1. `quota_service.py` 新增惰性单例 async Redis client（`redis.asyncio.from_url(settings.redis_url, decode_responses=True)`，仿 distributed.py 模式）。
2. 重写 `_check_rate_limit` 为 async：key = `quota:rl:{workspace_id}:{int(time.time() // 60)}`；`pipeline: INCR key; EXPIRE key 120`（仅当返回值为 1 时设置 TTL）；`count > limit` 返回 False。两个调用方（message_hub、workflows 端点）本就是 async，加 `await` 即可。
3. **降级策略**：捕获 `redis.RedisError` → `logger.warning`（每分钟至多记一次）→ 回退现有进程内滑窗（保留 L99-117 作 fallback，保证本地无 Redis 开发不被打断）。`reset_rate_limit_state()` 同时清内存桶（Redis 侧测试用唯一 key 前缀或 fakeredis/stub monkeypatch，不依赖真实 Redis）。
4. 在 `tasks.py` `POST /api/tasks` 创建路径补 `check_workspace_quota`，超限抛同款 `AppError(429)`（对齐 message_hub 行为）。
5. 测试：扩展 `backend/tests/test_quota_enforcement.py`——monkeypatch 假 Redis client（记录 INCR 调用与返回值序列）断言：①超限返回 False 且 key 格式正确；②Redis 抛错时回退内存桶且放行不崩；③现有 4 个内存滑窗用例继续通过（fallback 路径天然覆盖）。
