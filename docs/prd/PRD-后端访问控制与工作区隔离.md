# PRD：后端访问控制与工作区隔离

> 类型：新需求（Requirement）｜状态：已完成

## 1. 背景

Agent Console 当前按本地单用户工具设计，REST API 与 WebSocket 默认无需认证。服务一旦监听非本机地址，工作区数据、模型配置与管理接口会缺少最基本的访问边界。同时，Agent 工具执行必须继承当前任务的工作区上下文，不能由模型自行指定数据范围。

## 2. 目标

- G1：提供可配置的服务端 API Token，为 REST 与 WebSocket 建立统一访问门槛。
- G2：保持未配置 Token 时的本地开发体验，不改变现有默认启动方式。
- G3：工具调用始终继承可信任务上下文，并强制限定到当前工作区。
- G4：凭证接口只返回配置状态和掩码信息，不返回完整密钥。

## 3. 非目标

- N1：本阶段不建设用户注册、登录、组织、成员邀请和 RBAC 数据模型。
- N2：不修改 Agent 调度算法和模型供应商协议。
- N3：不提供已保存密钥的原文找回能力。

## 4. 功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR1 | 配置 `APP_API_TOKEN` 后，除健康检查和 API 文档外的 HTTP 请求必须携带合法 Bearer Token 或 `X-API-Key` | P0 |
| FR2 | 配置 Token 后，WebSocket 握手必须通过查询参数或请求头提供合法 Token | P0 |
| FR3 | 未配置 Token 时保持 local-first 兼容模式，并在日志中明确提示 | P0 |
| FR4 | Agent 工具执行上下文由 Orchestrator 注入 `workspace_id`，模型不能覆盖 | P0 |
| FR5 | Provider Key 查询只返回状态、来源和掩码，不返回完整值 | P0 |

## 5. 非功能需求

- Token 使用恒定时间比较，认证失败统一返回 401，不泄露校验细节。
- WebSocket 认证失败使用策略违规关闭码。
- 密钥相关响应禁止缓存。
- 工作区隔离必须有跨工作区自动化测试。
- 不配置 Token 时现有前端、测试和本地一键启动保持兼容。

## 6. 验收标准

- AC1：配置 Token 后，无凭证和错误凭证访问受保护 REST API 均返回 401，正确凭证通过。
- AC2：WebSocket 在配置 Token 时拒绝未认证连接。
- AC3：工具查询无法读取其他工作区的任务或 Agent。
- AC4：任何 Provider Key GET 响应均不包含数据库或环境变量中的完整密钥。
- AC5：完整后端测试、语法检查、依赖检查与 API 冒烟通过。
