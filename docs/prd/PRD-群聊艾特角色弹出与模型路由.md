# PRD：群聊艾特角色弹出与模型路由

> 类型：新需求（Requirement）｜状态：已完成｜目标：在群聊页面对话输入框中输入“@”时在对话框正上方弹出可艾特的角色列表，并支持通过姓名、角色标识、中文职责与模型等多维度检索；发送后后端精确解析并成功路由到对应角色的模型执行任务。

---

## 1. 背景与问题

在 Agent Console 多智能体协同运行台中，用户主要通过 `/chats` 群聊界面与多 Agent 协同工作。

在原有实现中，存在以下体验与路由断点：
1. **中文语境触发受限**：原有前端艾特判定依赖 `/(^|\s)@/` 正则，在中文无空格输入习惯下（例如“请问@测试专员”、“任务@Agent工程师”），无法触发角色候选菜单；且无法识别中文输入法下的全角 `＠` 字符。
2. **菜单弹出定位偏离**：原有的 MentionMenu 绝对定位挂载在最外层容器，菜单浮动在快捷指令区域上方，未严格贴合在对话框输入区域正上方，视觉上出现跳跃断层。
3. **角色检索维度单一**：仅支持按 Agent 的固定中文姓名进行包含匹配，无法按英文字段（如 `qa_engineer`）、模型名称（如 `code_model`、`review_model`）或角色职责标签（如 `测试专员`、`架构师`）进行过滤。
4. **后端路由缺少多维角色解析**：后端 `_select_agent` 主要依赖 `agent.name` 匹配，当用户通过角色英文名（如 `@agent_engineer`）、模型别名（如 `@code_model`）或通用简称（如 `@测试`、`@前端`）呼叫时无法命中目标，容易误回退至默认的项目总设计师。

---

## 2. 目标与非目标

### 2.1 目标

- **G1**：在输入框输入 `@` 或 `＠` 时，在对话框正上方紧凑弹出角色选择菜单，展示角色头像、名称、角色职责徽标、绑定模型与状态指示器。
- **G2**：支持中文句中无空格触发、全角/半角 `@` 兼容，以及输入文字后实时多维模糊匹配（名称、角色代号、模型代号、职责描述）。
- **G3**：完善键盘操作（上下方向键导航、Enter 选中补全、Escape 关闭）与光标精准就位（补全后自动追加空格并将光标移至末尾）。
- **G4**：后端 `MessageHub` 增强艾特解析，兼容按角色姓名、角色代号（`agent.role`）、模型名称（`agent.model_name`）与中文别名精准路由。
- **G5**：被艾特的 Agent 自动绑定到生成的 `Task` 中，并在执行时调用其配置的特定模型（`agent.model_name`，如 DeepSeek、Gemini、Claude、GPT 等）执行单 Agent 任务或由 Manager 发起编排。

### 2.2 非目标

- **N1**：不变更已有的任务状态机与任务入队逻辑。
- **N2**：不破坏既有的外部集成节点（如 `@Cursor`、`@Codex`）桥接调度逻辑（内部 Agent 依然保持优先）。

## 3. 用户故事

- **US1**：作为用户，我在群聊输入框中键入 `@` 时，希望立刻在输入框上方看到所有可用的协作角色卡片，清楚看到每个角色的职责和底层驱动的模型。
- **US2**：作为用户，我输入“请帮忙审查@测”时，候选菜单能根据“测”自动筛选出“测试专员（review_model）”，按回车即可快速插入 `@测试专员 ` 并继续输入。
- **US3**：作为用户，我习惯输入英文角色名（如 `@qa_engineer`）或模型名（如 `@code_model`）呼叫专业 Agent，系统能准确识别并将任务派发给该角色，使用该角色的专属模型完成任务。

## 4. 核心概念与系统交互

```
用户在输入框键入 @ / ＠
       │
       ▼
findMention 捕获光标位置与搜索词
       │
       ▼
ChatComposer 弹出 MentionMenu（位于对话框正上方）
展示：头像 + @角色名 + 职责徽标 + 模型标识 + 在线状态
       │
       ▼
用户选择（回车 / 鼠标点击）
insertMention 替换输入框文本，光标置于空格后
       │
       ▼
点击发送 -> POST /api/conversations/{id}/messages
       │
       ▼
MessageHub._select_agent 解析 @mention
（按 name / role / model_name / alias 匹配）
       │
       ▼
创建 Task (assigned_agent_id = 目标 Agent ID)
       │
       ▼
AgentOrchestrator 领取任务 -> call_agent_model
调用该 Agent 绑定的模型 (agent.model_name) 执行任务
```

## 5. 功能需求 (FR)

### FR1：触发与字符兼容
- 支持半角 `@` 与全角 `＠` 字符触发。
- 支持紧随中文字符、英文字符或标点符号输入时触发，不强制要求前面存在空格。
- 当光标移动到包含空格或其它艾特符号的文本后时，自动关闭候选弹窗。

### FR2：对话框上方定位与视觉呈现
- 候选菜单必须在视觉和 DOM 层级上以对话框输入容器作为相对定位基准，固定展示于输入框容器正上方（`bottom-[calc(100%+0.5rem)]`）。
- 菜单展示项包括：
  - 角色头像（或代号缩写）
  - `@角色名`
  - 角色职责标签徽章（如 `项目总设计师`、`Agent工程师`、`外部节点`）
  - 驱动模型标识（如 `模型: code_model`、`模型: review_model`）
  - 工作状态圆点指示（空闲、工作中、异常）

### FR3：多维度搜索过滤
- 输入 `@` 未输入后续字符时，默认展示工作区内所有按角色排序后的角色及外部节点列表。
- 输入后续查询文本时，支持多维匹配：
  - 角色姓名（如“测试专员”）
  - 角色标识（如“qa_engineer”、“agent_engineer”）
  - 角色标签（如“前端设计师”）
  - 模型代号（如“code_model”、“review_model”、“manager_model”）
  - 职责描述关键字（如“架构”、“代码”、“测试”）

### FR4：全套键盘与触控交互
- 上下方向键（`ArrowUp` / `ArrowDown`）循环切换高亮项。
- `Enter` 键确认选中当前高亮角色，自动在输入框替换为 `@角色名 ` 并在末尾补全空格。
- `Escape` 键关闭候选弹窗。
- 鼠标点击选项即时选中，光标保持聚焦在输入框合适位置。

### FR5：后端艾特多维路由解析
- 后端 `MessageHub._select_agent`：
  - 优先按精确 mention token 匹配 `agent.name`、`agent.role`、`agent.model_name` 以及预设别名表（`_ROLE_ALIASES`）。
  - 若未分词匹配（中文无空格直接连缀，如 `@测试专员帮我测试`），执行子串位置探测，按出现位置由前至后、匹配长度由长至短排序命中。
  - 内部 Agent 优先于外部集成节点；若均未匹配则兜底由默认 Manager 接收。

### FR6：精准模型调用与任务执行
- 任务生成时准确记录 `assigned_agent_id`。
- 编排调度器（`AgentOrchestrator`）调度该任务时，读取被指派 Agent 的 `model_name` 配置，调用相应的模型服务执行单 Agent 任务或由 Manager 发起编排，执行结果正常回灌至会话消息流。
