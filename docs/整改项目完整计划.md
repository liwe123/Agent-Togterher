## 1. 目标与完成定义

终局：从「多 Agent 任务运行台」升级为「可长期协作、上下文可治理、群聊可编排、安全可审计」的平台：

1. 协作语义完整：GroupChat 一等实体 + 一次一个 speaker 的 round 调度 + @ 交接 + PASS + 暂停/继续 + 交接工作树。
2. 记忆与上下文：bot/group/team 三作用域记忆、memory review、阈值与 checkpoint/part、全文检索。
3. 安全基线：httpOnly Cookie、Provider Key 独立主密钥、内容级脱敏、预算执行级控制、群管理员权限矩阵。
4. 历史闭环：不依赖宿主环境的缺口全部收口；E1-E3 完成验收补课。
5. 工程治理：CI 依赖可复验、本地门禁等同 CI、推送通道文档化、文档与代码同步。

全局 DoD：每批次按守则完成（类型判定 → PRD 三处同步（Requirement）→ 代码/测试 → A/B 或契约验证 → 独立子 Agent 验收 → 改动表重生成 → 推送 → CI 三 job 全绿 → 验收回写）；全量门禁与文档门禁见 §6。

## 8. 执行模型与批次流程

1. 批次规划：Lead 拆 shared task（write scopes + blocked_by），共享文件由 Lead 统一改。
2. 并行实现：后端/前端/迁移可由子 Agent 并行；不共享写作用域。
3. 中期验证：每 WP 完成即跑本地门禁；Batch 内合并到本地 main 再统一验收。
4. 独立验收：Batch 完成派独立子 Agent 核验；不通过 → 整改 → 复验。
5. 文档与推送：CURATED → 重生成 → 代理推送 → CI 轮询记录 run id → 进入下一 Batch。
6. 异常处理：CI 红先复现（SQLite + PG + Node 22）再修；代理不可用时记录并暂缓推送。
