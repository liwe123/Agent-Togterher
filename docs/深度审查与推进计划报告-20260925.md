## 三. 缺陷清单（按严重度）

### 3.1 P0 契约级缺陷（5 项）

#### 3.1.1 `resume-from-step` 假恢复【最高优先级】

**事实**（`backend/app/api/v1/endpoints/task_replay.py:117-156`）：

```python
step.status = "pending"          # L133 唯一改的 step 字段
step.finished_at = None          # L134
task.status = TaskStatus.PENDING # L135 唯一改的 task 字段
await db.commit()
# L146: custom_instruction 仅写入审计 detail，零执行用途
# L154: "已成功从步骤 X 恢复任务调度"  ← 文案撒谎
```

**全仓零调度动作**：无 `TaskService.enqueue`、无 `dispatch_background_task`、无 `run_workflow_dag`。orchestrator 无断点续跑能力，永远从头新建 step（`orchestrator.py:221-226`、`370-376`）。

**queue 模式必死锁**（生产默认 `config.py:32`）：
- 失败时队列项结算为 `dead`（`task_service.py:149-150`）
- `claim_next` 要求 `item.status=="queued"` 或租约过期，`dead` 项 `lease_expires_at=None` 永不匹配
- **坑**：即使补 `enqueue()`，`task_service.py:12` 的 `QUEUE_TERMINAL_STATUSES = {"completed","dead"}` 也不会复活终态项

**修复方案**（~15 行）：

```python
# 1) 删除并重建队列项（enqueue 不复活 dead 项）
item = await db.scalar(select(TaskQueueItem).where(TaskQueueItem.task_id == task_id))
if item is not None:
    await db.delete(item)
await db.commit()
await TaskService(db).enqueue(task)

# 2) 按模式调度
if get_settings().task_execution_mode == "inline":
    dispatch_background_task(task.id)

# 3) custom_instruction 真正用起来
task.description += f"\n\n【恢复指令】{body.custom_instruction}"

# 4) 文案改真话
"已重新调度任务（带历史上下文续跑）"
```

**应补测试**：queue 模式死信复活、inline 派发断言、resume 后真跑到终态、completed step 拒绝 409。

#### 3.1.2 `task_replay` 路由无鉴权 + IDOR

`task_replay.py:21` 的 `APIRouter(prefix="/tasks/{task_id}")` 无任何 `Depends`，对比 `cost_stats.py:26` `require_workspace_role("admin")`、`workflows.py:262` `require_workspace_role("member")`。且 `db.get(Task, task_id)` 无 workspace 过滤。

`tests/test_task_replay.py` **不带任何 Authorization 头就跑通了** —— 测试把未授权访问锁成了"预期行为"。

**修复**：加 `require_workspace_role("member")` + 经 task 反查 workspace 校验（对齐 C-196 隔离先例）。

#### 3.1.3 `test_command` 命令注入 RCE

`integration_service.py:128-131`：

```python
process = await asyncio.create_subprocess_shell(command, ...)
```

`command` 直接来自 `IntegrationDispatchRequest.test_command`（`schemas/integration.py:70`，max_length=2000，无白名单），`endpoints/integrations.py:204-207` 无任何 auth/RBAC 依赖，`schedule_node_dispatch`（`message_hub.py:90-95`）在 API 进程内后台执行 → **任意 shell 在 API 主机执行**。配合 3.1.4 = 未认证 RCE。

**修复**：`create_subprocess_shell` → `create_subprocess_exec` + 参数数组；或加命令白名单 + `require_workspace_role("admin")`。

#### 3.1.4 生产默认 open 模式零鉴权

`core/security.py:40-41`：

```python
def token_required() -> bool:
    return bool(settings.app_api_token)  # .env 中为空 → False
```

`main.py:71-75` 只有 `token_required()` 为真才鉴权。`.env` 实测 `APP_API_TOKEN=` 空、`JWT_SECRET_KEY` 未设 → **整个 API 零鉴权**，WS 同理（`security.py:59-60`）。docker-compose.yml:45 同样默认空。

**修复**：`app_env != "development"` 且 `app_api_token`/`jwt_secret_key` 均未显式配置时**拒绝启动**（fail-closed）；删 `auth.py:54` 硬编码 fallback `"agent-console-dev-secret-change-in-production"`。

#### 3.1.5 DAG 孤儿 WorkflowRun

`workflows.py:36-37` 的 `_background_dag_runs: set[asyncio.Task]` 只是进程内防 GC 引用，**无持久化归属标记**。API 进程崩溃时协程消失：

- 优雅停机收到 cancel 抛 `CancelledError`（`BaseException`），`dag_engine.py:489` 的 `except Exception` **兜不住** → `WorkflowRun` 永远停在 `running`
- `recover_expired_task_leases`（`task_lease.py:193-221`）只扫 Task，**完全不碰 WorkflowRun**
- 全仓对 `WorkflowRun` 的写入只在 `dag_engine.py:483/510`，零清理路径

**附带语义 bug**：崩溃后 inline 模式的 `recover_unfinished_tasks` 会用 `dispatch_background_task` → `run_task`（多智能体 orchestrator）重新执行，**而不是 `run_workflow_dag`** —— 产物完全不同。

**修复**（~6 行）：`task_lease.py` 循环内对同 task 的 running WorkflowRun 置 `failed`；lifespan 启动加兜底清理。

## 六. 安全面评估

### 6.1 全景

| 面 | 现状 | 判定 |
|---|---|---|
| 认证 | JWT HS256，access 15min / refresh 7d；**双 token 存 localStorage**；refresh 无轮换 | 弱 |
| 密钥 | PBKDF2 从 JWT secret 派生 Fernet；**硬编码 fallback** | **高风险** |
| 授权 | 4 级 RBAC（owner/admin/member/viewer）；`rbac_compat.py:63` 对无 user 请求跳过 RBAC | 有后门 |
| 审计 | 只记元数据，不记正文；`ip_address` 从未写入 | 基本干净 |
| 传输 | CORS 非 `*`；WS `?token=` 进日志 | **有泄漏** |
| XSS | 全前端 `dangerouslySetInnerHTML` 零命中；`<ReactMarkdown skipHtml>` | 干净 |
| SQL | 全参数化 ORM | 干净 |
| 反序列化 | 无 `pickle`/`yaml.load`（用 `safe_load`）；`tools.py:33` 的 `eval` 有 AST 白名单 | 干净 |

### 6.2 四项 REQ 风险等级

| REQ | 等级 | 攻击场景 |
|---|---|---|
| D2 | **高**（组合） | ① 任一 XSS = 7 天 refresh token 失窃；② WS `?token=` **已进 docker/采集日志**（uvicorn `websockets_impl.py:280-284` INFO 级打印）；③ cookie 化后需补 CSRF |
| D3 | **高** | 硬编码 JWT secret 是公开代码常量 → 任何人可派生 Fernet key → 拖库后**全部 LLM API key 明文还原**；同一密钥还可伪造任意 JWT |
| D4 | 中 | 纯装饰字段，虚假安全感；配合无鉴权 dispatch 可反复烧 token |
| D6 | 中-高 | 密钥形态内容进 `task_steps`/`model_calls`/WS/磁盘；DB key 不在 `_sanitize_error_message` 替换清单 |
