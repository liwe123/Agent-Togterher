### 租约场景设计

模拟一个"跑得比租约更久"的任务：

1. 建任务并入队，`claim_next()` 领取
2. 把 `lease_expires_at` 压到只剩 **1 秒**（模拟长任务把租约耗尽的临界状态）
3. B 组调用 `renew(item_id, token, lease_seconds=600)` 续租；A 组无此方法可调用
4. 让任务**继续跑 2.5 秒**，跨过原租约的过期点
5. 触发 `recover()`（Worker 的失联回收 sweep）
6. 观察队列项最终状态

## 4. 过程中确认的两个事实（对后续排障有用）

1. **alembic 会重配 logging**：`alembic/env.py` 里的 `fileConfig` 会覆盖 root logger 配置，导致应用自身的 `logger.info` 在迁移执行后不再输出（排查时 `app.worker` 的 "event relay started" 日志看不到即为此因）。**不要据此误判代码未执行到**，应单独调用目标函数验证。

2. **事件总线开启但无 Redis 时 `start()` 不报错**：`DistributedEventRelay.start()` 在无 Redis 环境下仍返回成功（Redis 连接是惰性的）。**切勿理解为"会自动降级"** —— 按 PRD §14 R2，发布侧无 try/except、订阅侧无重连，Redis 不可用时跨实例推送会静默失效，直到进程重启。
