# Agent Console 架构治理基线

> 对应《项目计划》Phase 0。本文只描述当前实现与后续演进边界，不新增产品能力，因此任务类型判定为 `Optimization`，无需新增 PRD。

## 1. 当前模块职责

| 模块 | 当前职责 | 边界约束 |
|---|---|---|
| Next.js 前端 | 控制台、群聊、任务、通讯录、设置页面；REST 查询与 WebSocket 状态刷新 | 不直接决定任务状态，不持有服务端租约或执行令牌 |
| FastAPI 接入层 | REST / WebSocket 路由、鉴权、参数校验、统一响应 | 只接入和编排调用，不承载长期执行状态 |
| `MessageHub` | 保存用户消息、解析 `@Agent`、创建待执行任务、广播创建事件、触发进程内调度 | 不执行模型调用；后续只依赖稳定的任务派发接口 |
| `AgentOrchestrator` | 领取任务、租约续期、单/多 Agent 执行、工具与模型调用、步骤持久化、结果广播 | 当前职责偏重；后续拆分时必须保持任务状态与事件契约兼容 |
| 模型与工具服务 | LiteLLM 路由、Provider 凭证、自定义模型、工具注册与执行 | 不直接修改任务主状态 |
| SQLAlchemy 数据层 | Workspace、Conversation、Message、Task、TaskStep、ModelCall 等持久化 | 当前 SQLite；迁移 PostgreSQL 时保持领域字段语义稳定 |
| WebSocket Manager | 按 workspace 维护进程内连接并广播事件 | 当前仅单进程可靠；不得被视为持久化事件源 |
| 启动恢复逻辑 | 扫描 pending 与租约过期 running 任务并重新派发 | 当前依赖 API 进程内调度，未来迁至独立 Worker / 队列 |

## 2. 任务执行主链路

```text
用户发送消息
  -> POST /api/messages 或兼容入口
  -> MessageHub 校验工作区活跃任务额度
  -> 保存 Message + Pending Task（同一数据库事务）
  -> 广播 message.created / task.status_changed
  -> 进程内 dispatcher(task_id)
  -> AgentOrchestrator 原子 claim：Pending -> Running + lease token
  -> 单 Agent 或 Manager -> Worker -> Reviewer -> Final 链路
  -> 持久化 TaskStep / ModelCall 并广播过程事件
  -> Running -> Completed 或 Failed，清除租约
  -> 保存并广播最终消息
```

重启恢复链路：

```text
FastAPI lifespan
  -> init_db + seed_defaults
  -> recover_unfinished_tasks
  -> Pending 任务 + 租约过期的 Running 任务
  -> 按 workspace 并发额度重新派发
```

## 3. 任务状态机基线

### 3.1 状态定义

| 状态 | 含义 | 是否终态 |
|---|---|---|
| `pending` | 已持久化，等待领取 | 否 |
| `running` | 已被执行器领取，持有有效租约 | 否 |
| `completed` | 执行成功且结果已持久化 | 是 |
| `failed` | 执行失败且原因已持久化 | 是 |
| `cancelled` | 任务被取消 | 是（当前仅预留枚举，尚无完整取消入口） |

### 3.2 合法转换

| 起始状态 | 目标状态 | 触发者 | 必要条件 |
|---|---|---|---|
| `pending` | `running` | Orchestrator / 未来 Worker | 条件更新成功；写入唯一租约 token 与过期时间 |
| `running` | `completed` | Orchestrator | 结果持久化；清除租约 |
| `running` | `failed` | Orchestrator | 错误原因持久化；清除租约 |
| `running` | `pending` | 启动恢复 / 未来租约回收器 | 租约缺失或已过期；清除旧租约 |
| `pending` | `cancelled` | 未来 TaskService | 当前未实现，落地前必须补 API、审计与并发测试 |
| `running` | `cancelled` | 未来 TaskService / Worker | 当前未实现，需要协作式取消和租约所有权校验 |

除表中转换外均应拒绝，尤其禁止客户端直接写入状态、结果和租约字段。终态任务默认不可重新执行；未来的“重试”应创建执行尝试记录或经显式状态机操作返回 `pending`，不能静默覆盖历史。

## 4. Trace / Correlation 标识规范

当前代码以 `task_id`、`conversation_id`、`workspace_id` 关联主要记录，尚未实现独立 trace 字段。后续实现遵守以下规则：

| 标识 | 生命周期 | 生成位置 | 传播范围 |
|---|---|---|---|
| `request_id` | 单次 HTTP / WebSocket 入站请求 | 接入层；优先接受合法 `X-Request-ID`，否则生成 UUID | 响应头、请求日志、由该请求直接产生的事件 |
| `correlation_id` | 一次用户意图及其派生消息/任务 | `MessageHub`；若上游已提供可信值则继承 | Message、Task、事件、后台派发日志 |
| `trace_id` | 一次任务执行尝试 | 成功 claim 时生成；重试生成新值 | TaskStep、ModelCall、工具调用、Worker 日志与事件 |
| `task_id` | 任务领域实体全生命周期 | 数据库 | 所有执行与审计记录 |
| `conversation_id` | 会话全生命周期 | 数据库 | 消息、任务和前端订阅上下文 |

格式统一为小写 UUID（数据库可存 UUID 类型或 36 位文本）。结构化日志必须至少包含 `event`、`request_id`（若存在）、`correlation_id`（若存在）、`trace_id`（若存在）、`task_id`（若存在）、`workspace_id`（若存在）以及异常摘要；禁止记录 API Key、Authorization、完整模型密钥或未经裁剪的敏感提示词。

## 5. 风险清单

| ID | 风险 | 影响 | 当前控制 | 后续动作 |
|---|---|---|---|---|
| R-01 | API 进程内调度，进程退出时后台协程中断 | 任务延迟或重复恢复 | 任务先持久化；启动扫描；租约 claim | Phase 2 引入持久化队列和独立 Worker |
| R-02 | SQLite 并发写与锁竞争 | 高并发下吞吐下降、提交冲突 | 工作区活跃任务上限；冲突转换 | Phase 1/数据库阶段引入 Alembic 并迁移 PostgreSQL |
| R-03 | Orchestrator 职责过重 | 修改风险和测试成本持续上升 | 单一 task id 入口；已有执行测试 | 抽离 `TaskService`、状态机、模型执行器和事件发布器 |
| R-04 | WebSocket 为进程内连接表 | 多实例事件丢失或只在单实例可见 | 单实例部署 | 引入 Redis Pub/Sub 或 NATS；事件分发与连接层解耦 |
| R-05 | trace/correlation 字段缺失 | 跨请求、任务和模型调用排障困难 | 通过 task/conversation 关联 | 按第 4 节落库并统一结构化日志 |
| R-06 | `cancelled` 仅有枚举，无完整语义 | 状态展示与真实能力不一致 | 暂无公开取消接口 | TaskService 落地时定义取消协议和测试 |
| R-07 | `create_all` + SQLite 手写补列 | Schema 演进不可审计、PostgreSQL 不适用 | 启动时兼容旧本地库 | 引入 Alembic，禁止继续扩展手写补列方案 |
| R-08 | 缺少持久化 outbox | 数据提交成功但广播失败时事件不一致 | 前端可重新拉取任务状态 | 队列/事件总线阶段设计 transactional outbox |

## 6. 演进边界图

```text
[Clients]
    |
[API / WebSocket 接入层]
    |  只做鉴权、校验、查询与命令受理
    v
[MessageHub] ---> [TaskService：状态机/幂等/租约/重试]
                       |
                       v
                [持久化 Queue]
                       |
              +--------+--------+
              |                 |
          [Worker]          [Worker]
              |                 |
        [Orchestrator 拆分后的执行组件]
              |
     [Model Gateway / Tool Runtime]

[PostgreSQL] <--- 领域状态 / 审计 / Outbox
[Event Bus]  <--- Outbox relay / Worker 事件 ---> [WebSocket Gateway]
[Observability] <--- 统一 logs / metrics / traces
```

强制边界：

1. API 不直接拥有长期执行协程；只提交命令并返回可追踪标识。
2. Task 状态只能通过 TaskService 的合法转换更新。
3. Worker 通过租约或队列可见性超时取得所有权，完成/失败必须校验执行尝试身份。
4. 领域状态以 PostgreSQL 为事实源；Redis/NATS 与 WebSocket 都不是事实源。
5. 事件发布必须可恢复，优先采用 outbox；消费者按 event id 幂等。
6. 模型网关和工具运行时只返回执行结果，不越权修改任务主状态。
